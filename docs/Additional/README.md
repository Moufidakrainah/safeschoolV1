# Additional Documentation

This folder gathers documentation produced by the team that goes **beyond** what the
subject explicitly requires (a single root `README.md` — see [`../Mandatory/`](../Mandatory/)).

It is referenced from the root `README.md` wherever extra detail or justification is
useful (e.g. module justifications, technical choices), so none of this work is lost —
it backs up and expands on the mandatory deliverable.

## Contents

| Folder | What's in it |
|---|---|
| [`design/`](./design/) | Design process: color palette, graphic charter, design system (supports the "Custom design system" module), initial mockups (March 2026) and final screenshots |
| [`technical/`](./technical/) | Deep dives on architecture, API, security, websockets, ELK, PWA, accessibility, file upload, SSR, stack, HTTPS implementation, etc. — backs up module claims and technical-choice justifications |
| [`process/`](./process/) | How we work: git workflow & howto, worktrees, collaboration guidelines, ESLint guide, React concepts, shadcn migration, and the ADR on doc tooling |
| [`project/`](./project/) | Product framing: vision, glossary, frameworks/libraries comparison, resources, Q&A |
| [`meetings/`](./meetings/) | Weekly meeting minutes (CRs) from March to June 2026 |
| [`manuel-reference-projet.md`](./manuel-reference-projet.md) | Extended reference manual covering technical decisions and rationale across the whole stack |
| [`safeschool_deroulement.html`](./safeschool_deroulement.html) | Walkthrough of the SafeSchool application flow |

## Note on AI usage

Much of this material was drafted with AI assistance (research, summarization,
explanations regenerated for clarity) and reviewed by the team. It is kept here as a
working knowledge base rather than discarded — see the root `README.md`'s
"AI Usage" section for how AI was used across the project.
